# GEAR — каталог автоуслуг

Независимый тестовый сайт для поиска автоуслуг в Беларуси. Интерфейс работает на Vinext/React, сервер запускается на Node.js. Новые опубликованные объявления читаются из Supabase PostgreSQL через Data API; 23 исходные демонстрационные карточки пока остаются в коде и отмечаются «Демо».

## Запуск локально

- Node.js >= 22.13
- `npm install --include=dev`
- `npm run dev` — локальная разработка
- `npm run build:node` и `npm run start:node` — проверка сборки для Render

Без переменных Supabase сайт продолжает показывать только демонстрационные карточки. Для подключения каталога задайте в окружении сервера:

```text
SUPABASE_URL=https://<project-ref>.supabase.co
SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
```

Не используйте секретный `sb_secret_...` или `service_role`: сайт читает каталог с публичным ключом и опирается на RLS. В репозиторий не добавляйте `.env` и настоящие учётные данные.

SQL-схема: [`db/migrations/0001_catalog.sql`](db/migrations/0001_catalog.sql). Сначала выполните её в SQL Editor проекта Supabase. Она создаёт таблицу `public.catalog_entries`, RLS-политику чтения только `status = 'published'` и одну вымышленную тестовую карточку. Для анонимных пользователей прав записи нет. На этом этапе новые объявления добавляет администратор через Supabase Table Editor: заполнить категорию из каталога, цену в BYN, город, адрес и координаты, телефон; проверить данные и перевести `status` из `draft` в `published`. Черновики и скрытые записи через сайт не видны.

`GET /api/catalog` возвращает опубликованные записи. Каталог, фильтры, карта и страница `/service/<id>` используют их без пересборки сайта. Регистрация, личные кабинеты, чат, отзывы, загрузка файлов, модерация и оплата пока не реализованы. Демонстрационную форму входа не следует использовать для реальных персональных данных. Перед рабочим запуском необходимы окончательные юридические документы, политика доступа, резервное копирование и проверка безопасности.

Настройки развёртывания — в [`DEPLOYMENT.md`](DEPLOYMENT.md).
